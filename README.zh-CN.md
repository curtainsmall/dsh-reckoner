## 安装

```sh
dsh plugin --profile <profile> add dsh-reckoner
```

| 情形 | 命令 |
|---|---|
| 已发布包 | `dsh plugin --profile <profile> add dsh-reckoner` |
| 本地检出 | `dsh plugin --profile <profile> add link:<path>` |

| 步骤 | 作用 |
|---|---|
| 该命令 | 把 `dsh-reckoner` 追加进 profile 的 `dsh.profile.bundles` |
| profile 启动 | 合并本包自带的 `dsh.bundle.patch`（`cordis.patch.yml`） |
| 该 patch | 插入插件行 |

## Reckoner 模式

本包附带两个智能体预设。会话在创建时选定其一。

| 预设 | id | 计算沙箱 | 外部检索 |
|---|---|---|---|
| **Reckoner** | `reckoner` | 六个插件工具，无网络 | 无 |
| **Reckoner with search** | `reckoner-with-search` | 同样的六个工具，外加 `search` | 一次一个事实，连同出处写进记录 |

| 规则 | 效果 |
|---|---|
| 该选哪个 | 除非问题需要外部事实，否则选纯粹的 `reckoner` 预设 |
| 为何必须当场定 | 会话一旦产出过内容，就无法再换预设 |

### 纯粹预设

| 方面 | 行为 |
|---|---|
| 工具面 | 只有六个插件工具：没有 shell、文件系统、网络与子代理 |
| 数字来源 | `set` 转录的值，或 `eval` 产生的结果 |
| 缺失的量 | 人设停下并指明该量 |
| 提问承载 | 每个提问都开启一条记录 |

记录中的引擎是可选的：需要数字的部分由 `set` 与 `eval` 承载，不需要数字的提问由记录自身的说明文字作答。

### 检索预设

| 方面 | 行为 |
|---|---|
| 工具面 | 六个工具，外加恰好一个工具 `search`，别无其他 |
| 通用检索 | `web_search` 与 `web_fetch` 两个预设都不挂载 |
| 后果 | 模型永远无法自行检索或抓取 |
| 问题 | 一次检索一个问题 |
| 答案 | 仅文字；查询词、页面与出处都不给它 |

| 记录保存 | 内容 |
|---|---|
| 问题 | 原样 |
| 候选 | 提供方返回的每一个候选出处 |
| 允许 | 策略允许的出处 |
| 来源 | 写出答案的抽取步骤所用的路由与提示词版本 |
| 策略 | 该预设行的配置：严格层级只保留允许列表上的参考资料主机 |
| 预算 | 一条记录默认最多四次检索 |

插件每次挂载都会把两个预设目录复制到 `$DSH_HOME/.agent-presets/`。两个预设都只提供人设，因为插件本身由 bundle patch 全局挂载。

## 计算引擎

每个宿主进程只有一个引擎，所有会话的工具调用都作用于它。它是一台不含领域知识的计算器：没有求解器、没有注册表、没有具名公式。它解析收到的值，在求值模型书写的公式时检查量纲，并记录每一次调用。

| 工具 | 作用 |
|---|---|
| `set` | 写入一个槽；`value: null` 删除该槽 |
| `get` | 读回一个槽；这是读取值的唯一方式 |
| `eval` | 把一条公式的结果写入 `target` 指定的槽 |
| `record_start` / `record_message` / `record_end` | 开启、批注并封闭一条记录 |

### 值

一个值由数字、复数（按直角坐标存储）、数组或对象，加上一个 SI 向量构成；向量的 7 个整数指数按 ISO 80000-1 顺序排列（m、kg、s、A、K、mol、cd）。

| `set` 接收 | 例子 | 说明 |
|---|---|---|
| 实数 | `{"num": 4500, "dim": "ohm"}` | |
| 复数 | `{re, im}` | 按直角坐标存储 |
| 复数 | `{mag, ang}` | 进入时换算 |
| 数组 | `{array: [...]}` | 整个数组共用一个向量 |
| 对象 | `{object: {...}}` | 每个字段各有一个向量 |

| `dim` 是 | 说明 |
|---|---|
| 表中的名称 | 表中只有 SI 名称 |
| 那 7 个整数 | 同一个向量的写出形式 |
| 省略 | 零向量 |

表外单位一律由模型在调用前换算。`degC` 是唯一的仿射名称，以开尔文存储。

### 公式

一条公式就是一个表达式。

| 写法 | 读取 |
|---|---|
| `@name` | 一个槽 |
| `@name[i]` | 一个元素 |
| `@name.field` | 一个字段 |

| `$` 记法 | 数量 | 可否求值 |
|---|---|---|
| 常量 | 5 | 可 |
| 一元函数 | 20 | 可 |
| 二元函数 | 4 | 可 |
| 有界形式 | 6 | `$sum`、`$prod`、`$seq` 可；`$integral`、`$limit`、`$diff` 只能写 |

| 规则 | 内容 |
|---|---|
| 运算符 | `+ - * / ^` |
| 乘法 | 必须写出：`*` |
| 没有 | 比较、逻辑、条件、赋值 |

### 量纲

量纲在求值过程中推导。

| 构造 | 规则 |
|---|---|
| 指数 | 必须无量纲 |
| 实数指数 | 按倍数缩放底数的向量 |
| 复数指数 | 要求底数无量纲 |
| `+` / `-` | 两侧向量必须相同 |
| `*` / `/` | 对向量做加减 |
| 分数向量 | 写入槽时被拒绝 |

### 回执

每次调用返回 `{ok: true, ...}` 或 `{ok: false, code, error}`。被拒绝的调用不改变任何状态，并给出 19 个稳定错误码之一。

## 记录

一条记录就是一次计算的过程：标题、求解所依据的条件、过程中的说明、求值步骤与可选的结束语。

| 标记 | 何时被拒 |
|---|---|
| `record_start {title}` | 记录已开启时 |
| `record_end {text?}` | 无记录时 |
| `record_message {text, hide?}` | 从不；`hide: true` 使该说明不进记录视图，但文章生成仍会收到它 |

| 规则 | 效果 |
|---|---|
| `set`、`get`、`eval` | 没有记录时一律被拒绝 |
| 封闭记录 | 清空槽表 |
| 因此 | 槽表非空恰好等价于存在一条未封闭的记录 |

| 磁盘上 | 路径 | 说明 |
|---|---|---|
| 未封闭的记录 | `<home>/open-record.jsonl` | 行写在这里 |
| 封闭 | 该文件被重命名为 `<home>/records/<id>.jsonl` | 封闭是原子操作，封闭的记录总是完整的 |
| 首行 | `{seq: 0, version: 1}` | 无此行或版本更旧者计为未知记录 |
| 未知记录 | 不会列出、提供或用于生成 | |
| 索引文件 | 无 | 列表由扫描 `records/` 得出 |

### 面板

| 项 | 值 |
|---|---|
| 入口 | 侧边栏同名入口 `Reckoner`，钢笔与直尺图标 |
| 路由 | `/api/dsh-reckoner/` 下的十一条 HTTP 路径 |
| 刷新 | 每 5 秒 |
| 标签页 | 两个：**记录** 与 **设置** |

| **记录** 给出 | 说明 |
|---|---|
| 已封闭的记录 | 一行一条 |
| 未封闭的记录 | 置顶显示 |
| 未知记录 | 一行红色的 `N 条未知记录`，点击即可删除这些文件 |
| 选中 | 以行的边框标示；没有复选框 |
| 打开记录 | 即进入其时间线，每个 `eval` 步骤一张卡片 |
| 隐藏的说明 | 仅在 **显示全部** 下显示，该开关的初值就是 **设置** 保存的偏好 |

| **设置** 给出 | 说明 |
|---|---|
| 生成默认值 | 每种文章格式一套 |
| 检索策略 | |
| 显示全部 | 上述显示偏好 |
| 等待重启 | 有改动等待宿主重启时显示一行 |

## 文章生成

每条已封闭的记录都可以写成一篇独立的文章。

| 写作者收到 | 说明 |
|---|---|
| 标题 | |
| 条件 | 仍然成立的那些 |
| 说明与求值步骤 | 按 `seq` 顺序交错 |
| 结束语 | |
| 数字 | 截到最多四位小数 |
| `hide: true` 的说明 | 以作者注交给写作者且不得写进文章 |

产品名只出现在固定标题 `DeepSeek Harness Reckoner Solution` 与固定作者行中。

| 格式 | 产物 |
|---|---|
| Markdown | 平铺的 `.md` 文件，从不编译 |
| LaTeX | `.tex` 源文件写入以文件名命名的目录，按需编译为 PDF |

| 每种格式各自记住 | 说明 |
|---|---|
| 输出目录 | 是 |
| 语言 | 是 |
| 是否编译 | 仅 LaTeX |

设置对话框以该格式记住的值打开，设置标签页编辑的是同一批值。文件名默认由记录标识符预填。PDF 编译交由 latexmk 或 MiKTeX 的 texify 完成，并需要 `xelatex` 引擎。勾选编译而没有可用驱动或引擎时，「生成」按钮禁用，对话框指明缺少的部分。

## 配置

| 设置 | 含义 |
|---|---|
| `DSH_RECKONER_HOME` | 插件主目录，默认 `~/.dsh-reckoner` |
| `DSH_RECKONER_LOG_LEVEL` | `debug`、`info`、`warn`、`error` 或 `off`；默认 `info` |

| 主目录存放 | 路径 |
|---|---|
| 未封闭的记录 | `open-record.jsonl` |
| 已封闭的记录 | `records/<id>.jsonl` |
| 插件状态 | `state.json` |
| 日志 | `logs/<YYYY-MM-DD_HH-mm-ss.SSS>.log` |

状态文件是一棵树：每个会记忆设置的模块一个子树，外加扁平的 `restartRequired` 标记。每次插件挂载写一个日志文件。
